# 虚拟屏要"先切屏再连接"，且切换权不能交给 Sunshine

**TL;DR**：虚拟屏解决的是"客户端分辨率不匹配 / 无头 / 关物理屏"，不解决稳定性。它让组件从 3 个变成 4 个，前提是切换动作发生在串流开始之前。

## 三条路线

| 路线 | 组件 | 适用 | 代价 |
|---|---|---|---|
| 不用虚拟屏 | 宿主 + 输入驱动 + 物理屏 | 客户端是标准分辨率 | 手机/平板会有黑边 |
| 官方 + VDD | 宿主 + 输入驱动 + VDD + 物理屏 | 要透明可控，愿意自己维护 | 装驱动、调 EDID、手动切屏 |
| 分支内置（基地版 / Vibepollo） | 宿主（含显示驱动）+ 客户端 | 要开箱即用 | 组件更多，工具链与上游有滞后 |

## 切屏交给谁：结论是交给 Sunshine 自己

早期结论（v0.4.0）是"切屏权移出去，由外部脚本在连接前切"。**2026-11-24 实测否决了这条路**：`global_prep_cmd` 在 `configure_display` 与 `probe_encoders` 之后才执行，那时捕获屏和编码器已按物理屏初始化；而且 `dd_configuration_option = disabled` 会触发后台 `revert_configuration()`，与编码器探测抢显示设备，把 launch 卡死。详见 [prep 命令改不了捕获屏](prep命令改不了捕获屏.md)。

现在分工是：

```text
平时：虚拟屏设备常驻启用，但不在桌面拓扑里（CCD 隐藏，见 [虚拟屏待机隐藏](虚拟屏待机隐藏.md)）
        ↓
Moonlight 连接
        ↓
Sunshine configure_display：ensure_only_display 只留虚拟屏（早于编码器探测，时序正确）
        ↓
probe_encoders → 会话建立 → 按客户端请求切分辨率
        ↓
断开：回滚物理屏
```

三条硬约束：

1. **虚拟屏设备不能禁用**——`probe_encoders` 必须能枚举到它，否则连接直接失败。
2. **`output_name` 必须写 `device_id`（GUID）**，不能写 `\\.\DISPLAYn`：编号在设备重新启用后会变，Sunshine 找不到就静默回退物理屏。
3. **`dd_configuration_option` 用 `ensure_only_display`**，不要用 `disabled`——后者会触发回滚，反而卡死。

回滚阻塞的残余风险见 [显示拓扑卡死](显示拓扑卡死.md)：设备常驻启用理论上能避开"目标设备已不在拓扑里"这个触发条件，但本机尚未做完整的连接—断开循环验证。

## VDD 的具体参数

`VirtualDrivers/Virtual-Display-Driver`（MIT，MikeTheTech 主导）：IddCx 1.10 **user-mode** 驱动，SignPath 代码签名，x64 无需测试签名；640×480 到 8K，60/144/240/500Hz 及 59.99 这类小数刷新率；自定义 EDID；HDR 10/12bit 需 Windows 11 23H2+。

```powershell
winget install --id=VirtualDrivers.Virtual-Display-Driver -e
```

配置在 `C:\VirtualDisplayDriver\vdd_settings.xml`。

## 已知失效场景

| 场景 | 后果 | 处理 |
|---|---|---|
| 显卡驱动大版本更新 | VDD 失效或黑屏 | 重装 VDD，导入 `vdd_settings.xml` 快照 |
| 用 DDU 清理驱动 | 大概率要重装 VDD | 同上 |
| VDD 重装 | 设备实例重建，`\\.\DISPLAYn` 编号变化 | 用 `device_id`（GUID）绑定则通常无感；编号绑定会静默回退物理屏，重跑 `Install-Vdd.ps1` 重新解析 |

**user-mode 驱动的意义**：它崩了不会蓝屏，最坏是黑屏或驱动失效，重启即可恢复。这也是它比内核驱动更适合"自己维护"的原因。

## 怎么验证

1. 平时：`dxgi-info` 只有物理屏；虚拟屏设备 `ConfigFlags=0` 但 `Attached=no`。
2. 连接后：`sunshine.log` 有 `New streaming session started` 与 `CLIENT CONNECTED`；虚拟屏分辨率等于客户端请求值（点不同卡片切换档位验证）。
3. 断开后：物理屏恢复，且日志里没有反复的 revert 记录。

# 局域网串流优先留在官方分支，只有需要虚拟显示器才换分支

**TL;DR**：选分支的决定因素是「客户端分辨率是否等于主机物理屏」，不是「哪个分支更稳」。需要虚拟屏才换，不需要就别换。

## 五类分支的现状

| 分支 | 维护状态 | 独有能力 | 代价 |
|---|---|---|---|
| 官方 LizardByte/Sunshine | 最活跃，稳定版 + 每日预发布 | 上游修复源头 | 无虚拟屏（要自己装驱动） |
| 基地版 Foundation Sunshine | 活跃，正式版/预发布双通道，节奏以天计 | 自带 Zako 显示驱动、HDR 全链路、桌面面板、配套客户端生态 | 组件最多；内核外多一层驱动；与上游安全修复有滞后 |
| Apollo | **功能冻结**：正式版停在 2025-07，仅零星安全提交 | 内置虚拟显示器 | 基线停在 2025 年，缺 2026 全年 Windows 修复 |
| Vibepollo | 非常活跃，稳定版 + nightly | 虚拟屏生命周期护栏、免费虚拟手柄驱动、WGC 服务模式捕获 | 单人维护，迭代快，签名与杀软误报 |
| Vibeshine | 活跃（Vibepollo 的同源直系分支） | 同 Vibepollo 的一套改良 | 作者自荐优先用 Vibepollo |

## 判断规则

1. **客户端都是 PC / 电视，分辨率是 1080p / 1440p / 4K 标准值** → 留官方分支，不需要虚拟屏。
2. **客户端是手机 / 平板，要求铺满无黑边，或主机无头、要串流时关物理屏** → 需要虚拟屏，走 [虚拟显示器方案](虚拟显示器方案.md)。
3. **不确定自己需不需要** → 先按 1 用一周。虚拟屏不是稳定性改进，它是**多一个组件**。

## 为什么不建议新装 Apollo

它的招牌是虚拟显示器，但正式版停在 2025-07，最后一次提交是 2026-05 补一个安全公告。拿它当"稳定版"，本质是把"不再更新"当成"不会出问题"，代价是少了 2026 年全部的 Windows 修复与安全补丁。合理定位是：**一个比你现有版本更老的基线**。

## 输入后端的成本变化（2026-09 起）

官方 2026.906 用 libvirtualhid 取代了 ViGEmBus。后果是：要「完整的驱动级手柄 + Raw Input 键鼠」，需要单独装 Virtual HID Driver 并**激活机器授权**。ViGEmBus 退化为 Xbox 360 / DualShock 4 的有限兜底。

这条直接造成了生态分裂——基地版、Vibepollo、Vibeshine 都选择自带免费虚拟手柄驱动，并把它当作卖点。

## 怎么验证

- 查你装的是哪个分支：`C:\Program Files\Sunshine` 下是否存在 `Zako` 相关组件；「应用和功能」里显示 `Foundation Sunshine` 即基地版。
- 查官方版本线是否前进：`https://api.github.com/repos/LizardByte/Sunshine/releases?per_page=5`，看 `prerelease` 字段为 `false` 的最新一条。

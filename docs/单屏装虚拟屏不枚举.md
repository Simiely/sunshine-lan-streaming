# 单屏机器装完 VDD，DXGI 里没有虚拟屏

**TL;DR**：驱动装好了不等于显示器接上桌面。单屏笔记本上必须主动 `DisplaySwitch.exe /extend` 一次，虚拟屏才会出现在 DXGI 里。这个坑有明确的判据，不用猜驱动是不是坏了。

## 现象

2026-11-24 在 `redmibookpro15x`（AMD Ryzen 7 7840HS / Radeon 780M，单屏 3200×2000）上装 MTT VDD：

- `devcon install` 返回 0，`ROOT\DISPLAY\0001`（`Root\MttVDD`）在注册表里 `ConfigFlags=0`，设备管理器里状态 OK；
- 但 `dxgi-info` 轮询 60 秒，始终只有 `\\.\DISPLAY1` 一个输出，分辨率 3200×2000；
- 安装脚本中止，报 `FAIL 无法唯一确定虚拟屏对应的 \\.\DISPLAYn`，`sunshine.conf` 未被改动。

## 根因

IddCx 驱动在单屏拓扑下创建了设备节点，但**没有自动把新显示器 attach 到桌面**。这与旧机器（4070S，多输出）的经验不同——那边驱动一装好 DXGI 立刻就能看到新屏。

判据三条同时成立即可确诊：

1. `Get-PnpDevice -Class Display` 里有 `Virtual Display Driver`，`Status=OK`；
2. `dxgi-info` 的 `Output Name` 只有物理屏一条；
3. 设备管理器里该设备无感叹号。

三条都成立时，问题在拓扑，不在驱动安装。

## 处理

```powershell
DisplaySwitch.exe /extend
Start-Sleep -Seconds 3
& "$env:ProgramFiles\Sunshine\tools\dxgi-info.exe"   # 应看到新输出
```

实测 `DISPLAY36` 在 extend 后立即出现（1920×1080，`AttachedToDesktop=yes`）。

`Install-Vdd.ps1` 已固化这个动作：**轮询 3 轮仍无新输出时自动执行一次 `/extend`**，多屏机器若已有输出则不触发。这个动作可逆、不改任何配置，也不会禁用物理屏。

## 一个连带坑：引号变成字面量

重跑时用 `-OutputName '\\.\DISPLAY36'` 显式指定，结果 `sunshine.conf` 被写成：

```text
output_name = '\\.\DISPLAY36'
```

引号成了值的一部分，Sunshine 认不出这块输出屏。根因是 cmd / `Start-Process -ArgumentList` 传参时保留了包裹引号。`Install-Vdd.ps1` 与 `Restore-Baseline.ps1` 现在都会在写入前剥掉首尾的单/双引号，并打印 `纠正参数` 提示。

## 怎么验证

```powershell
# 期望：两块屏都在，虚拟屏 AttachedToDesktop=yes
& "$env:ProgramFiles\Sunshine\tools\dxgi-info.exe" |
  Select-String 'Output Name|AttachedToDesktop|Resolution'
```

再看 `sunshine.conf` 的 `output_name` 必须是 `\\.\DISPLAYn`，前后不带引号。

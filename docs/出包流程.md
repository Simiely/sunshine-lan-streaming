# 出包只有两步：先拉资产，再打 zip

## 为什么要把下载放到构建阶段

安装时联网有三个具体麻烦，而且都在真机上出现过：

- GitHub 的 CDN 会间歇性返回 `502`。实测 Moonlight 便携包连续 6 次失败，第 7 次才成功。
- 大文件中途断流。VDD 的 71 MB 包第一次只下到 26 MB，哈希对不上，装到一半才发现。
- 目标机可能根本没有外网，而"装到一半需要联网"是最难解释的失败方式。

把下载锁在构建阶段，这些风险就只影响出包的人，不影响收包的人。

## 两条命令

```powershell
powershell -ExecutionPolicy Bypass -File tools\build\Fetch-Vendor.ps1
powershell -ExecutionPolicy Bypass -File tools\build\Build-Package.ps1
```

第一条按 `manifest/components.json` 拉取三个组件包和许可证全文，落到 `payload\vendor\` 与 `payload\licenses\`。
第二条校验后组装并打包，产出 `dist\sunshine-lan-streaming-<版本>.zip`。

两条命令都是幂等的：已存在且哈希匹配的资产直接跳过，可以反复执行。

## 产物是什么样

解压后的根目录直接就是可操作的文件，没有多余的一层文件夹：

```
一键部署.cmd          依次完成安装、虚拟屏、卡片，最后统一弹窗
安装.cmd              安装 Sunshine 与基线配置
安装虚拟屏.cmd        可选：启用虚拟显示器
恢复基线.cmd          退回物理屏方案
恢复显示.cmd          显示异常时的救援
使用说明.txt          给第一次打开的人
scripts\              PowerShell 脚本
conf\                 虚拟屏分辨率预设
licenses\             GPL-3.0 / MIT 全文
vendor\               三个组件包（msi / zip / zip）
manifest\             components.json，安装脚本据此校验版本与哈希
```

## 怎么验证产物是好的

不要只看"zip 能解开"。真正的判据是解压后安装脚本能不能找到东西：

```powershell
Expand-Archive dist\sunshine-lan-streaming-0.4.0.zip -DestinationPath dist\verify -Force
powershell -ExecutionPolicy Bypass -File dist\verify\scripts\Install.ps1 -DryRun
```

看到这两行才算通过：

```
OK   安装包存在: Sunshine-Windows-AMD64-installer.msi
manifest: ...\dist\verify\manifest\components.json
```

`-DryRun` 只做检查与计划输出，不安装、不改配置，非管理员也能跑。

`Build-Package.ps1` 自己也会做一次解压自检，逐项确认 13 个关键文件在位，
顺带验证中文文件名在解压后没有乱码。

## 两个容易漏的校验

**先比大小，再比哈希。** 只比 SHA256 的话，下载不完整的文件也要整个读一遍才发现问题；
`size_bytes` 写进 manifest 后，残缺文件在第一步就被拦住。

**哈希不符要重试，不能直接判死。** 传输损坏和文件被替换看起来一样，
但前者重下一次就好。当前实现是下载 → 校验 → 不符则删除重下，最多两轮。

## 断流时的正确姿势

`curl -C -` 从断点续传，配合多轮外层重试。实测在连续 `502` 的情况下，
文件长度会一轮一轮往上爬（0 → 24.8 MB → 33 MB → 37.2 MB），最终成功。

两个必须注意的点：

- PS 5.1 在 `$ErrorActionPreference='Stop'` 下，原生程序往 stderr 写一行就会抛
  `NativeCommandError` 直接打断脚本——重试循环第一轮就死了，看起来像"重试没生效"。
  调用 curl 期间必须临时降级为 `Continue`，并把 `2>&1` 里的 `ErrorRecord` 过滤掉。
- curl 的 `--retry` 默认不重试 HTTP 错误，要加 `--retry-all-errors` 才会对 `502` 重试。

## 边界

- `dist\` 与 `payload\vendor\*.zip|msi|exe` 都不入 git。二进制靠构建期按 manifest 取，仓库只存"怎么取"和"取到什么算对"。
- `payload\licenses\*.txt` 会入库。它们是纯文本、体积小，而且 GPL-3.0 再分发要求随附全文，属于必须可追溯的内容。
- 本流程不含 Windows 端 APK。手机、平板、电视的客户端需各自在应用商店安装。

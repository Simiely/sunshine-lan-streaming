# 官方只有一个版本适合长期停留：2026.516

**TL;DR**：2026.516（2026-05-16）是最后一个"老架构"稳定版，组件最少；2026.914 是最新稳定版但继承了新架构的全部风险；中间的 2026.906 应直接跳过。

## 时间线

| 版本 | 日期 | 通道 | 定位 |
|---|---|---|---|
| `v2025.924.154138` | 2025-09-24 | 稳定 | 更老的稳定版，缺 2026 年修复 |
| `v2026.516.143833` | 2026-05-16 | 稳定 | **最后一个老架构稳定版** |
| `v2026.906.222525` | 2026-09-06 | 稳定 | 架构重写第一版，问题集中 |
| `v2026.914.233613` | 2026-09-15 | 稳定 | 当前最新稳定版 |
| `v2026.1123.40502` | 2026-11-23 | 预发布 | 每日构建，不进主力机 |

两个稳定版之间隔了两个月，稳定版与预发布之间隔了两个多月——这个节奏本身就说明新架构仍在收敛。

## 2026.906 改了什么

一次性动了三件事，这是回归集中的直接原因：

1. **输入后端**：libvirtualhid 取代 Inputtino（Linux）与 ViGEmBus（Windows AMD64 主后端）
2. **托盘**：全平台迁到 Qt（无桌面会话时会因平台插件缺失直接 abort）
3. **安装包**：NSIS `.exe` 停产，只剩 WiX `.msi`；便携包改名 `lite.zip`

同一版本还修了 5 个 GHSA 安全公告——这是它必须发布的真实理由。

## 已知问题（Windows）

| 版本 | 问题 | 命中条件 |
|---|---|---|
| 2026.914 | 断开时阻塞约 2 分钟甚至崩溃 | 多显示器 + `ensure_only_display` + `output_name`，详见 [显示拓扑卡死](显示拓扑卡死.md) |
| 2026.914 | 服务起不来 `StartService FAILED 4551` | 开启 Windows 智能应用控制，拦截未签名 `sunshine.exe` |
| 2026.914 | 启动慢 10–20 秒 | 普遍现象，不影响串流 |
| 2026.516 | 装到非 C 盘时安装器挂在 PATH 步骤 | 装到 `C:\Program Files\Sunshine` |
| 2026.516 | 装完手柄无反应 | 该版起不再自动安装 ViGEmBus，需手动装 |

## 结论

- **长期停留**：2026.516。组件最少，无虚拟屏、无新输入层。
- **要新架构**：等 11 月这批预发布转正后的下一个稳定版，不要停在 2026.914。
- **要虚拟屏**：不要指望官方版本线，转 [虚拟显示器方案](虚拟显示器方案.md)。

## 怎么验证

- 装机版本：看启动日志首行 `Sunshine version: ...`，或「应用和功能」里的显示版本。
- 官方列表：`https://api.github.com/repos/LizardByte/Sunshine/releases?per_page=5`，`prerelease=false` 的第一条就是当前稳定版。

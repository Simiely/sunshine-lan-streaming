# 4070S 从零部署闭环：装完即可串流，断开回到隐藏态

**TL;DR**：从空环境执行安装包，Sunshine 2026.516.143833 与 MTT VDD 25.7.23 自动装好，配置、卡片、凭据、防火墙一次到位；虚拟屏在待机时隐藏，Moonlight 连接后由 `ensure_only_display` 拉起（实测 apply 约 0.33 秒），断开回滚、两块物理屏位置不变。**未闭环**：ViGEmBus 自动安装在本机被卸载残留的 `StopPending` 服务挡住，需干净机器复测；局域网自动发现仍受虚拟网卡组播影响。

## 一、环境

| 项 | 值 |
|---|---|
| 宿主 | 4070S，`COMPUTERNAME=4070S`，device_id `4070s` |
| 物理屏 | R27qe Gen2 ×2，2560×1440 @ 120，位置 `0,0` / `-2560,0` |
| 业务网卡 | `10.4.240.16/23`（默认路由） |
| 宿主软件 | Sunshine `2026.516.143833`，MTT VDD `25.7.23` |
| 客户端 | OPPO Find X9 Pro，Moonlight 手动添加主机 `10.4.240.16` |

## 二、部署结果

安装脚本自检全部通过（0 失败项），结果文件 `C:\ProgramData\sunshine-lan-streaming\devices\4070s\sync-4070s-result.json` 关键字段：

```
success=true
synced_at=2026-11-25T18:52:24
topology=SUMMARY mode=multi physical=2 virtual=0 action=hidden
sunshine_installed_now=false  vdd_installed_now=false
```

独立复核：`SunshineService` Running / Automatic，47984、47989、47990 均监听，Sunshine 防火墙规则 2 条，`admin` 登录 Web UI 返回 HTTP 200；6 张分辨率卡与 6 张封面部署完成（含 Desktop / Steam Big Picture 共 8 张卡）。

## 三、连接-断开实测（sunshine.log 原文摘录）

```

18:47:40.963  Current display device configuration: [两块 R27qe Gen2]
18:47:40.964  New display device configuration: [仅 VDD]  change is needed: true
```

apply 阶段 0.957 → 1.284，约 **0.33 秒**走数据库快路径；断开回滚后复查桌面仍为两块 2560×1440，虚拟屏不在活动拓扑（`physical=2 virtual=0`）。

## 四、踩到的坑（与产品无关，但会挡住复测）

- **ViGEmBus 卸载残留**：手工卸载时先删了正在运行的内核驱动文件，SCM 里的服务对象卡在 `StopPending`；此时 `sc stop` 报 `1061`、`sc delete` 报 `1072`，安装器返回 0 却无法重建服务。**这是清理顺序造成的残局，不是必须重启**——按 [正确顺序](../ViGEmBus卸载残留不必重启.md)（设备节点→停服务→删服务→删驱动包）清理后可当天重装。
- **自动发现走错网卡**：主机 mDNS 应答来自 RayLink 虚拟网卡 `172.30.243.173`，手机在 WiFi 侧扫不到。手动添加 `10.4.240.16` 不受影响；这是组播出口问题，不是端口或防火墙问题（47989 本机连通测试通过）。

## 五、结论与仍缺的证据

- 成立：从零安装、配置落盘、凭据可用、虚拟屏待机隐藏、连接拉起、断开回滚。
- 未成立：ViGEmBus 自动安装在干净机器上的闭环；局域网广播域内的自动发现。
- 因此按 [DEVELOPMENT.md](../../DEVELOPMENT.md) 的发布规则，本报告**不能作为发布 zip 的依据**，`status: active`，待两项补齐后归档。

## 附：2026-11-26 复测补充

早上 09:04 的一次会话暴露了配置缺口：`sunshine.conf` 里没有 `dd_config_revert_on_disconnect`，Sunshine 缺省为 `disabled`。日志在 09:04:43 只有 `CLIENT DISCONNECTED`，没有 `Trying to revert applied display device settings`，桌面停在虚拟屏仍在拓扑的状态，物理屏没有自动恢复。09:04:06 的 `Trying to reset persistent display device settings` 只是重置持久化设置，不等于回滚。

已在本机补写 `dd_config_revert_on_disconnect = enabled` 并重启服务验证配置已加载；v0.6.1 起该键写进虚拟屏基线。上文“断开回滚成立”的结论**仅在应用关闭路径下观察到**，不能作为发布依据。

## 附：2026-11-26 v0.8.2 面板快捷方式复测

- 桌面「Sunshine 控制台」改由 `wscript.exe` 运行 `Open-Panel.vbs` 隐藏拉起 `Panel.ps1`；双击后不出现命令行窗口，只弹浏览器。
- 实测（4070S，18:27）：冷启动到 `http://127.0.0.1:47991/` 就绪约 3.2 秒，浏览器完整加载 UI（`webpanel.log` 中 `/assets/*`、`/api/config` 均为 200）；代理按需常驻，空闲 10 分钟退出。
- 踩坑：VBS 含中文注释时 WSH 会静默不执行（按系统 ANSI 读 UTF-8），改为纯 ASCII 注释后稳定；细节见 [免登录面板](../免登录面板.md)。
- 结论：快捷方式入口在本机成立；串流链路结论不变，仍以 §三 的连接-断开日志为准。

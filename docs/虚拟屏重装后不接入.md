# 重装 VDD 后设备一切正常，Windows 却不把虚拟屏接回桌面

**TL;DR**：设备管理器全绿、DXGI 却没有虚拟屏，先看显示数据库是不是把这台显示器记成了“不接入”。用 `Hide-Vdd.ps1 -Show` 走 CCD 接回，比反复重装驱动有效。

## 现象

2026-11-26 在 `4070S`（RTX 4070 SUPER，两块 2560×1440）上，一键卸载后重新部署：

- `devcon install` 返回 0，`ROOT\DISPLAY\0001` 状态 OK；
- `Get-PnpDevice` 里 `Generic Monitor (VDD by MTT)` 有一个 `CM_PROB_NONE` 的实例，其余是历史 phantom；
- DXGI 只有 `\\.\DISPLAY1` 和 `\\.\DISPLAY2` 两块物理屏，等待 60 秒不变；
- `Install-Vdd.ps1` 报 `FAIL 无法唯一确定虚拟屏对应的 \\.\DISPLAYn`，退出码 4。

## 根因

[待机隐藏](虚拟屏待机隐藏.md) 会把 VDD 的 path 从活动拓扑移除，并带 `SDC_SAVE_TO_DATABASE` 写进显示数据库。设备被卸载再重建后，Windows 按数据库恢复这块屏“已存在但不接入”的状态——所以 PnP 与监视器对象都正常，DXGI 却看不到它。

这和 [单屏笔记本缺 extend](单屏装虚拟屏不枚举.md) 是两回事：那边设备从未接入过，`DisplaySwitch /extend` 一次就出现；这边是数据库明确记着“不要接入”，`DisplaySwitch` 不一定生效。

## 处理

脚本已内置回退顺序，无需手工干预：

1. 第 3 秒仍无新输出 → 调用 `Hide-Vdd.ps1 -Show`，用 CCD 把 VDD 接回桌面（只动 VDD，不动物理屏）；
2. 第 8 秒仍无 → `DisplaySwitch.exe /extend`；
3. 第 14 秒仍无 → 再试一次 CCD。

同时删掉了“设备存在且有输出就视为就绪”的快捷判断——虚拟屏未接入时物理屏也有输出，这个条件会提前放行并导致后面的识别失败。

手工恢复：

```powershell
powershell -ExecutionPolicy Bypass -File Hide-Vdd.ps1 -Show
Start-Sleep -Seconds 2
& "$env:ProgramFiles\Sunshine\tools\dxgi-info.exe"
```

## 验证

修复后重跑 `Install-Vdd.ps1`：CCD 接回后识别到 `\\.\DISPLAY3`（1920×1080），写入 `output_name = {5eb52002-...}`，随后重新隐藏，结束状态 `SUMMARY mode=multi physical=2 virtual=0 action=hidden`，退出码 0。

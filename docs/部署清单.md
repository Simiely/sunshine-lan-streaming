# 局域网串流上线前要过的六道检查

**TL;DR**：只跑通一次不算部署完成。六项的判据是"每一步都能验证"，最后一项决定了出问题能不能回到能跑的状态。

## 一、确认版本与分支

```powershell
Get-ItemProperty "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*" |
  Where-Object { $_.DisplayName -like "*Sunshine*" } |
  Select-Object DisplayName, DisplayVersion
```

判据：显示的具体版本号与你文档里记录的一致。官方线参考 [版本矩阵](版本矩阵.md)；分支选型参考 [分支选型](分支选型.md)。

## 二、确认服务在跑且能自启

```powershell
Get-Service SunshineService | Select-Object Name, Status, StartType
```

判据：`Status = Running` 且 `StartType = Automatic`。若 `Stopped` 且 `StartType = Manual`，说明它依赖桌面 GUI 手动启动——重启电脑后忘记开，就是一类"偶发连不上"。

## 三、确认三个网络开关

在 `sunshine.conf` 中：

| 键 | 值 | 原因 |
|---|---|---|
| `origin_web_ui_allowed` | `lan` | 注意：`lan` 意味着同网段**任何设备**都能打开 47990 |
| `upnp` | `disabled` | 开了 UPnP，路由器可能自动把端口映射到公网 |

外加路由器侧：**不做 47984–47990 的端口转发**。三条都对，"只在局域网"才成立。

## 四、排除与之抢捕获的软件

判据：向日葵、ToDesk 这类远程桌面软件在串流时不运行。它们同样做屏幕捕获，可能抢占 capture 或自带虚拟显示器。

```powershell
Get-Service | Where-Object { $_.DisplayName -match "AweSun|ToDesk|Sunlogin" } |
  Select-Object Name, Status
```

## 五、跑一次完整的连接—断开循环

判据：断开后数秒内可再次连接，且日志里搜不到：

```text
Trying to revert applied display device settings
```

若出现五次以上，见 [显示拓扑卡死](显示拓扑卡死.md)。

## 六、存一份快照

这是"不需要维护"的真正实现方式——不是不出问题，而是出问题能回到能跑的状态。

| 内容 | 位置 |
|---|---|
| 配置与配对证书 | `C:\Program Files\Sunshine\config\` 整目录 |
| 显示配置 | `MultiMonitorTool.exe /SaveConfig` 导出的正常 / 串流两份 cfg |
| 虚拟屏配置 | `C:\VirtualDisplayDriver\vdd_settings.xml`（若使用 VDD） |
| 版本清单 | 宿主版本、输入驱动版本、VDD 版本、显卡驱动版本 |

判据：快照里每一项都能说出"怎么恢复"。说不出来的那一项，就是下次故障时卡住的地方。

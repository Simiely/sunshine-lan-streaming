# 多设备部署前先固定设备 ID 与硬件画像

**TL;DR**：[配置清单](配置清单.md) 只规定"怎么取、合格线在哪"，不规定"当前值是多少"。跨机部署时，当前值必须挂在设备 ID 下——否则 A 机的结论会被当成 B 机的证据，这正是 36 项状态互相覆盖的根因。

## 设备 ID 规范

```text
device_id = 小写(COMPUTERNAME)，非 [a-z0-9-] 的字符替换为 -
例：REDMIBOOKPRO15X → redmibookpro15x
```

选 `COMPUTERNAME` 是因为它在体检脚本、状态文件、报告名里都能直接取到，不需要额外配置。**不要**用 IP 当 ID——DHCP 会变；也不要用序列号当目录名——不便检索。

同时记录硬件指纹用于核对（镜像克隆后 `COMPUTERNAME` 可能重复）：

| 字段 | 取法 |
|---|---|
| `uuid` | `Win32_ComputerSystemProduct.UUID` |
| `vendor` / `model` | 同上 `Vendor` / `Name` |
| `cpu` | `Win32_Processor.Name` |
| `memory_bytes` | `Win32_ComputerSystem.TotalPhysicalMemory` |
| `gpu[]` | `Win32_VideoController`：`Name` / `AdapterCompatibility` / `DriverVersion` |
| `os` / `os_build` | `Win32_OperatingSystem.Caption` / `BuildNumber` |
| `nics[]` | `Get-NetIPAddress`：`InterfaceAlias` / `IPAddress` / `PrefixLength` |
| `displays[]` | `WmiMonitorID.Active` + 当前分辨率与刷新率 |
| `encoder` | 最近一次串流日志的 `Creating encoder [...]`；未串流则记 `unknown` |

## 最低与推荐硬件

这是**基线**，不是性能排行榜。不达最低线的机器不进入"通过"判定；达到推荐线的机器才适合做长期停留的宿主。

| 项 | 最低 | 推荐 | 判定依据 |
|---|---|---|---|
| OS | Windows 10 `10.0.19041` / x64 | Windows 11 `10.0.26100` | `manifest.components.json` 的 `min_os`；VDD HDR 需 23H2+ |
| CPU | 4 核 64 位 | 8 核 / 16 线程 | 编码走 GPU，CPU 只做捕获与封装 |
| GPU | 支持硬件编码（NVENC / AMF / QSV 任一） | 独显 NVENC，且驱动非 DDU 后未重建 | F-01 从日志取，不预设 `nvenc` |
| 内存 | 8 GB | 16 GB | 宿主常驻 + 捕获缓存 |
| 显示 | 至少 1 个活动输出，或已确认的无头方案 | 物理屏分辨率 = 客户端标准档位 | E-01；无头必须准备退路 |
| 网络 | 与客户端同广播域，可互相直达 | 宿主有线 + 客户端 5 GHz | D-01 / I-03；宿主热点不算局域网 |
| 电源 | 可禁用睡眠与快速启动 | 已禁用 | H-01 / H-02 |
| 冲突软件 | 串流时可停用抢捕获软件 | 未安装向日葵 / RayLink / ToDesk | G 组 |

**显卡厂商不是硬基线**：库里第一台机器是 NVIDIA RTX 4070 SUPER（`nvenc`），第二台是 AMD Radeon 780M（只能走 `amf`）。[设备矩阵](设备矩阵.md) 里两台并存；把 F-01 的合格线写死成 `nvenc` 会让所有 AMD/Intel 宿主永远不合格。

## 设备配置覆盖

包内只放通用默认 `conf/devices/defaults.json`；某台机器需要偏离默认时，放 `conf/devices/<device_id>.json`，由脚本按 ID 自动加载。优先级：**命令行显式参数 > 设备专属 > defaults > 脚本内建兜底**。

可覆盖的键（都是原来写死在脚本里的本机值）：

| 键 | 含义 | 不覆盖时的风险 |
|---|---|---|
| `anchor_resolution` | 虚拟屏识别锚点，必须避开物理屏原生分辨率 | 物理屏也是 1920x1080 时认屏失效 |
| `physical_resolution` | 物理屏原生分辨率，用于校验锚点 | 无 |
| `expected_initial_resolution` | VDD 首次加载的分辨率，不再硬编码 800x600 | 换驱动版本后判据失效 |
| `nic_allow_pattern` / `nic_deny_pattern` | 业务网卡与干扰网卡的别名正则 | 换机器后网卡名不匹配，D-04 误判 |
| `conflict_services[]` | 抢捕获服务名列表 | 换机器后漏检新的远程软件 |
| `other_idd_pattern` | 第三方虚拟屏品牌正则 | 误把别人的 IDD 当成自己装的 VDD |
| `gpu_vendor_pattern` | 本机显卡识别正则 | 只认 NVIDIA 会漏 AMD / Intel |
| `vdd_output_strategy` | `snapshot-diff` / `explicit` / `auto` | DISPLAYn≥10 的启发式在别机上不成立 |

## 归档规则

- 报告文件名：`<date>-<device_id>-<主题>.md`，例 `2026-11-24-redmibookpro15x-本机基线.md`。
- 状态文件目录：`C:\ProgramData\sunshine-lan-streaming\devices\<device_id>\`，含 `device.json`、`display-state.json`、`install-result.json`、`credentials.txt`、体检快照。**不再使用固定文件名**，否则多机互相覆盖。
- [配置清单](配置清单.md) 的状态列只记"最近一次核验摘要"；多机结论一律以对应设备的报告为准。

## 怎么验证

```powershell
powershell -ExecutionPolicy Bypass -File payload\scripts\Get-Baseline.ps1 -Json
```

输出必须带 `device_id` 与 `fingerprint` 两个字段；把该文件按上面的命名规则归档到 `docs/reports/`。同一台机器重跑，除发生过变更的项外状态必须一致。
